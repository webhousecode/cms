# F168.1 — Kode-illustrationen er usynlig i lys tilstand

**Status:** in progress · **Parent:** [F168](./F168-visuelle-fejl-paa-skaermen.md) · **Meldt:** Christian, 2026-08-25, med skærmbillede

> "Denne illustration virker ikke i light mode."

## Målt i en browser, ikke bedømt ud fra billedet

På det levende site med lys tilstand tvunget:

```
kodetekst : lab(2.75 0 0)     — sort
panel     : rgb(10, 10, 10)   — sort
```

Kontrasten er altså ca. 1:1. Hver linje der ikke er farvet er væk: `import { defineConfig } from`, `export default defineConfig({`, `collections:`, `name:`, `fields:`, `type:`. Tilbage står de tre farvede strenge og de grå kommentarer — præcis det man ser på Christians skærmbillede.

Titellinjen har den modsatte fejl: den males med `bg-card/50`, som i lys tilstand er næsten hvid. Så der ligger en hvid strimmel oven på et sort panel, med en 50 %-gennemsigtig grå etikette ingen kan læse.

## Rodårsagen, i én sætning

Panelet er **fast mørkt** (`bg-[#0a0a0a]`), mens dets ramme og dets tekst kommer fra **sidens tema**. Et element der altid er mørkt kan ikke låne farver der vender.

Det er ikke en enkeltfejl: samme konstruktion findes to steder — CMS-illustrationen på forsiden og tech-stack-panelet på /ai.

## Rettelsen

Én komponent, `CodeWindow`, med sin **egen** faste palet: panel, titellinje, streger, etikette og kodetekst. Begge steder bruger den. Så kan det tredje sted ikke drive fra de to andre — samme grund som at adressen på CMS'et nu står ét sted.

## Bevis

Se acceptkriterierne. Kernen: kontrasten regnes ud af de to faktiske farver i en rigtig browser i **begge** tilstande. Et skærmbillede der ser fint ud beviser ikke at teksten er læsbar — det var præcis et skærmbillede der viste at den ikke var.
