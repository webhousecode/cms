# F206.4 — schema-sync tager også blocks

Del af F206 (hvert site bygger selv; webhouse.app er kun CMS). Repoet er kilden til schemaet; webhouse.app holder en kopi af cms.config.ts som admin redigerer efter.

## Motivation

trail committede 2/10 en ny forside (broberg-ai/trail@a174b2c) med 9 nye sektionstyper (salesHero, stats, loop, everywhere, business, proof, trailsTeaser, pricingTeaser, cta). Admin læser trails schema fra kopien `/data/cms-admin/beam-sites/trail/cms.config.ts` (fra 3/5) — 0 af typerne findes der, så Christian kan ikke redigere dem.

`POST /api/schema/sync` (F159) synker collections og forms, men ignorerer `blocks` med vilje. Blok-definitionerne (felterne i hver sektionstype) bor kun i config'ens `blocks`-array, så der er ingen API-vej. En PUT af pages med nye blok-navne ville give typer uden felter. At skrive filen via ssh er forbudt (root-ejerskab + to kopier uden vej tilbage).

## Scope

- `BlockDef` + `replaceBlocksArray` + `writeConfigBlocks` i `lib/config-writer.ts`, samme mønster som forms (F159/25 aug): erstat kun top-level `blocks: [...]`, tilføj før `storage:` hvis det mangler, guard mod tabte collections/blokke, `.bak` før skrivning.
- `POST /api/schema/sync` accepterer `blocks`: upsert pr. name, aldrig slet, identisk gen-sendelse = no-op, `invalidateActiveSite()` efter skrivning.
- Tests i `config-writer.test.ts` + sync-route.
- Derefter: trail sender sine blocks (eller cms gør det én gang via API'et med trails token).

## Non-goals

- At læse config direkte fra repoet (F206-sporet; kræver at intet site-kode kører på serveren).
- Sletning af blokke via sync.

## Risiko

config-writer har før slettet felter (2026-05-19, 2026-06-07). Derfor: kun array-span erstattes, alt andet byte-identisk, og testene beviser det.

## Reuse

Genbruger forms-mønstret i config-writer og sync-ruten; ingen ny pakke.
