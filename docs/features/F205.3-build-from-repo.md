# F205.3 — Byg fra sitets eget repo

Del af F205. Målt 2/10-2026: trailmem.com bygges fra `/data/cms-admin/beam-sites/trail/build.ts` på webhouse.app's volume, sidst ændret 3/5-2026 (Beam-snapshot). trails push til `broberg-ai/trail` når aldrig live; kopien afviger ~435 linjer fra `apps/landing/build.ts` på main. En kontrast-rettelse måtte håndlægges ind via SSH (backup `build.ts.bak-20261002-accent`).

Mål: en site-agent retter sin kode i sit eget repo, kalder deploy med sin egen nøgle, og det er live. Ingen kopi der kan drive.

## Scope

- Site-registry får en valgfri kobling: repo + sti + branch (fx `broberg-ai/trail`, `apps/landing`, `main`).
- Deploy: hvis koblet, hent build-koden fra repoet (shallow fetch af stien på den branch) ind i et frisk arbejdsdir, kør build mod CMS-indholdet, udgiv; deploy-svaret nævner sha.
- Ukoblet site: uændret adfærd.
- GitHub-adgang: genbrug den GitHub-token cms allerede bruger til github-pages-deploy (`resolveToken`).

## Non-goals

- At flytte indhold ud af CMS'et. Indholdet bliver i CMS; kun build-koden kommer fra repoet.
- At slå det til for trail før trail har sammenlignet main mod kopien (AC 4).

## Åbne spørgsmål

- Afhænger build.ts af andre filer i repoet (styles, assets, package.json-deps)? Måles på trail før design låses.
- Node-moduler til build: installeres pr. deploy eller caches pr. site?

## Reuse

cms' eksisterende github-pages-deploy og `resolveToken`. Ingen ny pakke.
