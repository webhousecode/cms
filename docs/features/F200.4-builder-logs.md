# F200.4 — Build-loggen virker

**Kilde:** components 29/9-2026 (release-rapport @broberg/deploy-core 0.6.0), del af Christians ordre om at alle Fly-kald går gennem deploy-core.

## Fejlen (målt af components, read-only)
`streamBuilderLogs` kaldte `GET api.machines.dev/v1/apps/<app>/machines/<id>/logs`. Den adresse findes ikke hos Fly (404 «page not found»). Koden behandlede kun `res.ok` og slugte resten i en tom catch — så build-loggen for SSR-deploys har aldrig vist en eneste linje, og intet gik rødt. Testene var grønne, fordi de mockede et `{ logs: [...] }`-svar fra den ikke-eksisterende adresse.

## Rettelse
- `@broberg/deploy-core` 0.5.0 → 0.6.0 (additiv: `getMachineLogs(app, machineId, { nextToken })`, som taler med Fly's rigtige logs-API med `FlyV1`-auth).
- `streamBuilderLogs` poller med den returnerede `nextToken`, så kun nye linjer hentes (ingen tidsstempel-dedupe).
- Fejl rapporteres via `onError` (default `console.error`). En permanent afvisning (4xx undtagen 408/429) stopper polling.
- De nu døde hjælpere (`FLY_API_BASE`, `DEFAULT_TIMEOUT_MS`, `flyHeaders`) fjernes.

## Tests
Fly's rigtige svarformat (`data[].attributes`, `meta.next_token`); beviser at 2. kald sender `next_token` fra 1.; permanent 404 rapporteres og stopper. Mutation-tjekket.

## Reuse
`@broberg/deploy-core` (owner components).
