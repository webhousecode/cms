# F201.17 — cms på flådens fælles hemmeligheds-port

## Motivation
F201.16 viste at cms' egen gitleaks kørte med nul regler, og et Discord-webhook lå seks måneder i det offentlige repo. Christian 1/10: «Ja, bed components bygge den fælles kontrol». components leverede `secret-gate` (F090.1, tag `secret-gate-v1`): en genbrugelig GitHub-workflow der først selvtester (planter falsk PAT, Discord- og Slack-webhook og fejler hvis ikke alle tre fanges) og derefter scanner hele historikken med en delt config.

## Scope
1. `.github/workflows/secret-gate.yml` på hver push og PR — også docs, som deploy.yml ignorerer, og som var der lækket lå.
2. `deploy.yml`: `deploy` kræver nu `[gate, secret-gate]`.
3. `.gitleaksignore`: de 12 historik-fund gennemgået ét for ét, fingerprint + begrundelse (dødt webhook, bevidst PSI-nøgle, Supabase demo-JWT'er, testfixtures, lokal dev-token afvist af prod 401).

## Non-goals
Fjerne repoets egen `.gitleaks.toml` (bruges stadig af pre-commit-porten).

## Reuse
`broberg-ai/components` secret-gate (F090.1).

## Rollout
Commit + push → første kørsel grøn → meld antal fund til components (F090.2).
