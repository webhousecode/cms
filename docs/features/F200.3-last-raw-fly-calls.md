# F200.3 — De sidste rå Fly-kald

**Ordre:** Christian 29/9-2026 via components: kalder kode Fly.io's API, skal det gå gennem `@broberg/deploy-core` (`FlyClient`). `flyctl deploy` i CI er ikke omfattet.

## Målt 29/9
| Sted | Kald | Status |
|---|---|---|
| `components/deploy-wizard/step-connect.tsx` | browser → `api.fly.io/graphql` (list orgs) med brugerens token | flyttes: `FlyClient.listOrgs()` findes |
| `lib/build-orchestrator/fly-machines.ts:204` | `api.machines.dev/.../machines/<id>/logs` | **mangel i deploy-core** — ingen logs-metode; meldes til components, bliver indtil pakken har den |

Alt andet (createMachine, waitForExit, docker-stream) går allerede gennem FlyClient (F200.1).

## Arkitektur
- Ny server-rute `POST /api/admin/deploy/fly-orgs` `{ flyToken }` → `new FlyClient({ token }).listOrgs()` → `{ orgs: [{slug,name}] }`. Gatet med `requirePermission("deploy.trigger")` (samme rettighed som selve deployet).
- `step-connect.tsx` kalder ruten i stedet for Fly direkte. Fejl fra Fly (401 osv.) omsættes til en læsbar fejl; en tom liste er stadig en fejl («No organizations found»).
- Tokenet forlader stadig browseren — det gør det i dag også (til Fly); nu går det til vores egen server, som i forvejen får det i docker-stream-ruten.

## Non-goals
- Logs-kaldet omskrives ikke udenom pakken (ingen lokal workaround — pakken udvides hos components).

## Reuse
`@broberg/deploy-core` (owner components).
